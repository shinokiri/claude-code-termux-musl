# 专用分析采集入口：1.6.0

对象为 Claude Code 2.1.296 / Bun 1.4.3 / 官方 ARM64 musl 包，审计日期 2026-10-11。
在 1.5.0 已拆分共享项目分类器的基础上，`optional-off` 再停止四类独立分析入口。
本轮改变的是采集开始的位置；已关闭的事件总线和请求出口继续作为后续控制点。

## 来源、消费者与处理

这些入口依据当前嵌入程序的实际调用链识别。相同短符号在其他模块可能表示不同函数，
替换只绑定到校验过摘要的模块与导出，不做全局文本替换。

| 专用入口 | 已检查的消费者 | 原有采集 | 1.6.0 的返回与保留项 |
| --- | --- | --- | --- |
| `projectRepository.analytics`，`chunk-z4p55bfk.js` 的 `aRo` | 启动事件；公共导出 `getGitPresenceForAnalytics` | Git 存在、远程存在及远程主机类别 | 返回 `null`；保留共享 Git 检查和远程地址查询 |
| `fileAnalytics.collect`，`chunk-zp1p6m2t.js` 的 `d0n` | 启动预热；上下文度量的 `project_file_count_rounded` | 为数量统计运行文件枚举，缓存取整后的结果 | 异步返回 `undefined`；保留其他搜索和文件服务方法 |
| `permissionAnalytics.collect`，`chunk-6sj4m1a5.js` 的 `bbn` | 启动和权限可用性变化的事件；公共分析导出 | 自动模式可用性、设置来源、策略来源等 10 个字段 | 返回空对象；保留实际权限判断、策略执行和模式状态接口 |
| `accessibilityAnalytics.collect`，`chunk-9mpcwcwg.js` 的 `tRs` | 启动事件 | 屏幕阅读器是否启用及启用来源 | 返回空对象；保留启用状态、状态文本和子进程辅助功能环境 |

没有替换混合用途的启动流程和上下文度量大函数：它们还等待工具、MCP、用户上下文等业务
初始化。单独替换文件数量入口同时覆盖预热和事件消费，不需要关闭共享文件服务或拦截所有
文件枚举。Git、权限和辅助功能采用相同原则。

两个额外候选未增加控制：当前 `Iot` 的实现直接返回空对象；`LZe` 可能组装的 namespace /
cluster 字段，在本构建中来自返回空值的提供者。它们可在代码中出现，不等于当前实际采集了
集群信息。后续版本需要重新检查，不能用本版本的空实现推断未来行为。

## 对照与升级门槛

`tests/privacy-collectors.mjs` 通过异步作用域归属观察文件读取、Git 提供者调用以及文件枚举
子进程，只保留计数、类型和字段名。组件对照包含原始模式、1.5.0 关闭模式和本轮策略。
测试显式启用合成的屏幕阅读器状态，避免用本来就关闭的功能产生假阴性。

| 合成组件场景 | 原始模式／1.5.0 optional-off | 1.6.0 optional-off |
| --- | --- | --- |
| Git 分析，直接调用和公共导出 | 两次调用均有 3 个结果字段；共 2 次 Git 配置读取 | 两次均返回 `null`，作用域内读取与提供者调用为 0 |
| 项目文件数量 | 返回数字，观察到一次文件枚举 | 返回 `undefined`，枚举为 0 |
| 权限分析，直接调用和公共导出 | 10 个结果字段，组件对照有 6 次文件读取 | 空对象，作用域内读取为 0 |
| 辅助功能分析 | 2 个结果字段 | 空对象，作用域内读取为 0 |
| 共享功能接口 | Git 查询、权限状态／可用性、辅助功能状态／文本／子进程环境正常 | 同样通过 |

完整 CLI 对照使用独立 HOME、假 API key、本地 TLS 接收器和合成 Git 项目。1.5.0 下四入口
确实被调用，观察到两次 Git 配置读取、一次文件枚举和上述分析字段。1.6.0 下四入口仍被调用
并完成，但返回约定的空结果，观测到的作用域内读取、枚举和远程查询均为 0。权限组件的六次
读取只属于组件场景；完整 CLI 的原权限入口已使用缓存，不能将组件读数套用到 CLI。

两版都完成 Bash 的 `git remote get-url` / `git status`、Read 和三次本地模型请求，接收器
没有收到事件上报。其他工具、后台、DNS/TLS、Worker、自启动和 48 个项目识别场景继续运行。
完整 CLI 新增为第 14 项安装验收 `privacy_collectors`，失败则不切换当前版本。
公开的[机器可读证据](audits/2.1.296-collector-privacy.json)只含摘要、字段名、计数和合成标记检查。

```bash
python tests/privacy-smoke.py --root /完整候选版本/runtime --report /临时目录/privacy.json
python tests/privacy-dataflow.py --root /完整候选版本/runtime --collector-check --output /新的临时目录
```

旧安装的对照可额外传入 `--collector-profile /当前源码/libexec/privacy-profile.json`，它只为
观察器提供经过摘要检查的定位信息，不在旧进程安装新的关闭策略，不更改持久模式。

隐私档案最低修订号升为 4，校验 32 个模块，新增覆盖生产者、公开重导出及上下文度量消费者。
这些摘要表示受检代码匹配，不表示 32 个模块的全部功能已审计或停用。关闭模式拒绝直接回退
到缺少本轮控制的 1.5.x；未知官方版本仍须复核后才能自动升级。

## 业务请求的附加字段仍需分别判定

本轮还继续追踪了[1.4.0 数据流审计](architecture-review.md)发现的模型请求附带信息。
出现在业务请求里，不能直接视为任务所必需；客户端可控制该字段，也不能单独证明删掉它
符合所有服务端契约。本轮未把下列字段加入默认删除策略。

| 字段 | 从程序确认的链路 | 尚未证明的部分 |
| --- | --- | --- |
| `x-claude-code-prev-tool-durations` | 工具名与耗时序列化，最多 32 项／4096 字符；独立的头写入函数用于流式请求和非流式回退 | 服务端能否普遍接受缺省；移除发送字段与保留本地计时应分别处理 |
| `diagnostics.previous_message_id` | 有条件加入前一条响应标识；客户端含该字段的 HTTP 400 错误分类 | 错误分类只证明客户端预期校验，不证明该字段必填；它与真正用于会话续接的 `thread.previous_message_id` 不同 |
| metadata 的 `device_id` / `account_uuid` / `session_id` | 由身份构造器组装；设备 ID 来自随机配置标识，远程路径还可附加其他关联字段 | 各身份与远程分支的必需性及服务端去关联效果；不能将未追踪的远程字段直接称为认证凭据 |
| 条件性环境头 | 第一方路径、功能开关和其他条件决定是否组装，包含权限／环境等状态 | 真实账号的开关分配及服务端用途；本地开启开关的观测不能推断所有用户都有此头 |
| system 中的 `x-anthropic-billing-header` 文本 | 版本、入口、提示和轮次等归因字段在请求体里；环境退出选项在部分分支会被忽略 | 不能把该开关宣传为通用关闭方式；也不能仅凭构造器中的 `cch` 占位值推断完整后续处理 |

上述结论来自本地程序和合成接收器，不是对服务端风控、保留期限或训练用途的证明。
其他事件调用方仍可能先构造参数再进入已停用的总线；本轮只证明四个明确入口的额外采集
停止，没有提供整个程序、native 出口、所有扩展、真实账号或 Remote Control 的覆盖证明。
