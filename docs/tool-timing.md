# 工具耗时：1.7.1 恢复官方行为

Claude Code 2.1.296 / Bun 1.4.3 / ARM64 musl，验证日期 2026-10-11。
`optional-off` 保留其他控制，但撤回 1.7.0 对 `prevToolDurations` 的屏蔽和对自定义耗时头的删除。
这项调整保留原程序的决定权，不强制启用耗时发送，也不改写用户的设置文件。

## 从程序确认的含义与条件

`x-claude-code-prev-tool-durations` 序列化上一轮工具名及毫秒数：有限数值取整、负数归零，
最多 32 项、4096 个字符。这个字段本身不包含命令、路径或工具返回内容；正常模型上下文
仍包含完成任务需要的工具调用及结果，删除耗时头不能隐藏这些工具活动。

原判断先读取 `CLAUDE_CODE_GATEWAY_HINT_HEADERS`；显式 `0` 禁用，`1` 启用。
未设置时，官方直连启用，其他路径按原提供方及功能开关条件决定。我们检查了实际程序的
三态布尔解析、直连判定、耗时格式化及请求构造链，并以真实 CLI 做对照。
官方也将这组头及其默认值、关闭选项列在[网关协议](https://code.claude.com/docs/en/llm-gateway-protocol#gateway-hint-headers)
和[环境变量](https://code.claude.com/docs/en/env-vars)中。

它是可省略的诊断信息，但不是官方直连默认关闭的信息。1.7.0 仅移除耗时头，保留其余
gateway hint 头，并不完全等同于原程序的整组关闭选项。考虑耗时数据的有限增量隐私收益，
1.7.1 恢复原行为以减少这项请求差异；这不等于认定服务端一定要求它，或所有上报都应保留。

## 控制层的改动

查询包装器仅在查询前重新清理缓存诊断配置，然后把原 `this`、全部参数及返回值完整传递。
不复制或遮蔽选项，不提前读取属性，不替换原 Promise／异步迭代器。
自定义头过滤器只处理缓存诊断 beta，耗时头与其他无关头保持原字节交给官方构造器。
原构造器仍可能按自身规则处理自定义头；适配器不替它决定最终值。

事件、错误上报、OTLP 导出、内置插件遥测、项目与专用分析采集，以及缓存诊断控制保留。
`DISABLE_TELEMETRY`、`DISABLE_GROWTHBOOK`、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
仍不由适配器设置。`CLAUDE_CODE_GATEWAY_HINT_HEADERS` 也不由适配器设置或覆盖。

## 对照与更新验收

本地 TLS 接收器、假 API key、隔离 HOME 和合成工具驱动真实 CLI；报告只保留计数、字段名
与条件检查。原始模式、1.7.0 关闭模式及 1.7.1 关闭模式的对照可复现：

| 场景 | 1.7.1 行为 |
| --- | --- |
| 默认普通查询 | 3 次模型请求的耗时项数为 `0, 1, 1`，与原始模式一致；1.7.0 关闭模式为 `0, 0, 0` |
| 完整响应查询入口 | 保留相同耗时行为，真实 Bash／Read 工具完成；该入口内部可能仍使用流式传输 |
| 流式失败恢复 | 两次空事件流后触发非流式恢复，5 次请求的耗时项数为 `0, 0, 1, 1, 1` |
| 自定义耗时头 | 模型及 bootstrap 保留原行为；缓存诊断与诊断 beta 仍移除，温度及其他自定义值保留 |
| 官方 gateway hint 关闭选项 | 原始与关闭模式均无耗时、请求分类和 prompt ID 头，工具任务照常完成 |
| 其他控制及功能 | 关闭模式无缓存诊断和事件批次；提示缓存、身份字段、归因文本及受测的条件环境头保留 |

`privacy_requests` 安装验收包含 9 个场景，与其他 14 项候选验收一起通过后才能切换版本。
最低档案修订号仍为 5，37 个受检模块摘要不变；回退到 1.7.0 会恢复旧版的耗时屏蔽，
关闭模式仍拒绝直接回退到缺少缓存诊断控制的 1.6.x。未知官方新版仍需先复核隐私档案。
