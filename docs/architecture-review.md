## 判断依据

“更根本”需要同时考察：控制点距问题成因有多近、覆盖哪些调用路径、依赖何种接口，以及
依赖变化时如何发现失效。代码位于更低层、拥有更高的进程内控制能力，并不单独证明这些条件。

| 机制 | 对应成因与当前控制点 | 已有依据 | 仍然存在的边界 |
| --- | --- | --- | --- |
| 公开启动器 | 初次进入 musl 前清理 Bionic loader 环境，保存给后续 Termux 工具使用 | 本轮裸 ELF 直接继承 Termux `LD_PRELOAD` 时加载失败；改用已安装的公开启动器后完成审计 | 构造函数运行之前，动态加载器就可能尝试加载不兼容库；ELF 自动依赖不能代替这项入口职责 |
| ELF 自动依赖 | 让受支持的 Claude 自启动进程独立加载兼容库 | 已有多代精简环境、自启动、后台会话验收 | 加载器机制稳定，但写入元数据的方式依赖已检查的 ELF 布局和固定安装路径；它不证明业务控制完整 |
| musl/Bionic 执行层 | 在执行程序时选择加载器环境，处理解释器与路径差异 | 已有 53 个执行用例及真实 CLI 工具测试 | 处理已支持的 libc 入口，未形成对直接系统调用、所有静态程序的通用隔离 |
| `getaddrinfo` DNS | 把普通地址解析接到 Android DNS 服务 | 本机 Android 地址查询、TLS 及错误语义测试 | 使用 `dnsproxyd` 实现协议，有 Android 平台维护成本 |
| c-ares DNS | 将默认 DNS 传输接到 Android，同时保留 c-ares 的记录解析和计时行为 | 多 API、Worker、错误、并发、大响应与持续测试 | 合成配置、socketpair 和线程是实质桥接成本；替换为更低层拦截不会自动消除它 |
| 隐私组件控制 | 在已识别的初始化、采集回调、队列和导出点分别处理 | 组件对照、原始 API 文件记录、真实 CLI 与后台测试 | 不同控制点分别证明不同阶段被停止；模块摘要不是整个模块功能都被停用的证明 |
| HTTP 请求控制 | 丢弃已识别的可选上报请求 | 独立接收器、fetch/HTTP/HTTP2 对照 | 知道出口不等于知道所有数据来源；正常业务请求中的附加字段仍会通过 |
| 更新与存储 | 签名鉴别适配包；验收和原子切换保护工作版本；租约保护运行中的文件 | 已有签名、升级拒绝、回退、清理与进程租约测试 | 生命周期保障不增加隐私语义覆盖；未知隐私版本仍需等待验证 |

实现与平台边界另见[执行层](native-execution.md)、[DNS 层](native-dns.md)、
[现行隐私模式](privacy.md)。本轮未修改运行库、DNS、TLS 和执行行为。

## 数据流及控制阶段

下表将“采集停止”“队列停止”“发送停止”分开。它不是对全程序全部路径的清单。

| 数据流 | 来源 → 组装 / 保存 → 消费或发送 | 1.4.0 optional-off 的位置 | 证据与下一控制点 |
| --- | --- | --- | --- |
| 内置遥测插件 | 受控能力接口读取环境、身份和仓库 → 生命周期采集 → 事件批次 | 不安装采集生命周期回调，替代模块不申请相应能力 | 已有组件对照支持该组件的读取、探测、定时器、发送均停止；不能推广到其他项目探测器 |
| 普通事件调用方 | 业务状态或额外探测 → 构造参数 → 事件总线 → 队列 / 导出器 | 总线及下游停用 | 本轮辅助观测仍收到预先构造的事件参数；需继续区分共用业务状态与遥测专属探测 |
| 项目环境分类 | 列举项目及有界读取配置 → 缓存分类 → 初始化事件 **及项目识别系统消息** | 事件发送被停用，分类采集仍运行 | 合成 `.npmrc`、`.envrc` 在辅助运行中确实被读；直接停用整个入口会同时移除系统消息，见下文 |
| 配置级设备 ID | 读取配置 `userID`，缺失时生成随机 32 字节 → 持久化 → 模型 metadata 与功能开关属性 | 保留 | 两条请求与新建测试配置中的 ID 相同；静态来源是随机配置标识，不能把字段名直接解释为硬件 ID |
| 会话 ID / 关联字段 | 会话状态 → 模型 metadata、请求头及功能开关属性 | 保留 | 本轮请求中的会话标识相互一致；需要按关联用途评估，不能仅删除一个出口字段就视为完成去关联 |
| 功能开关属性 | 客户端身份 / 平台 / 版本等 → 属性构造器 → `/api/eval/*` | 保留共享功能判断及请求 | 实测 API-key 路径仍发送 `id`、`deviceID`、`sessionId`、`platform`、`appVersion`、`entrypoint`、`userType` |
| 模型附加诊断 | 上一条模型响应标识 → `diagnostics.previous_message_id` → `/v1/messages` | 保留 | 后两轮值与本地夹具提供的上一条响应标识匹配；服务端是否允许移除未验证 |
| 工具耗时 | 工具执行记录 → 工具名 / 毫秒数序列化 → `x-claude-code-prev-tool-durations` | 保留 | 后两轮模型请求各有一个条目；输出头与本地计时用途应分别评估 |
| 系统文本归因 | 客户端版本、入口、提示和轮次等 → `x-anthropic-billing-header` 文本 → 模型 system | 保留 | 字段实际位于请求体，域名封禁及仅检查 HTTP 头均不能充分处理 |
| 条件性环境信息 | 功能开关 → 环境、权限与沙箱状态构造器 → `x-claude-code-wiggly-dove` | 保留 | 普通空开关夹具中没有；本地开启对应开关后 3/3 模型请求出现。没有验证真实账号是否分配该开关 |
| 模型任务内容 | 用户输入、工作目录、工具结果 → 模型消息 / system | 保留 | 合成提示、路径、Bash 和 Read 结果出现在接收器；这些来源包含正常任务内容 |
| OAuth / Trusted Devices / Remote Control | 身份与会话注册状态 → 相应业务协议 | 未整体停用 | 静态定位不能代替真实账号或远程会话验收；当前不宣称相关字段都可删除 |

功能开关属性模板里还存在账号、组织、订阅、邮箱等可选字段，但“模板可以容纳某字段”
不证明本构建的普通用户路径会提供它。例如当前默认身份实现的 `email()` 返回空值。
这次未进行真实 OAuth 登录，不能把静态模板字段列成已观察到的账号数据外发。

## 新发现：共享采集器使“整块关闭”产生额外行为变化

原程序的项目分类入口位于 `chunk-fhxt14z7.js` 的 `Vbn`。它会列举项目，调用有界读取接口
检查软件仓库配置、密钥管理工具引用以及平台工程标记，缓存分类结果。

本轮辅助观测用 `AsyncLocalStorage` 将这些读取归属于实际项目采集调用，避免混入同时进行的
正常 Read 工具或其他启动读取。探针只记录测试文件类别、是否返回文本、长度上限和字段名，
不读取或保存返回文本内容。测试目录仅含人工生成的配置及 Android 工程标记。

| 同一合成 Android 项目的对照 | 现行 optional-off + 观测 | 仅在测试中停用整个项目分类入口 |
| --- | --- | --- |
| 项目采集入口被调用 | 是 | 是，立即返回空结果 |
| 该入口下的 `.npmrc` / `.envrc` 文本读取 | 4 次，共两种文件 | 0 次 |
| 生成项目分类字段 | 16 个 | 0 个 |
| 排入系统消息队列的 `dev_intent` | 1 条 | 0 条 |
| 同一组 Bash / Read 任务及 3 轮模型请求 | 完成 | 完成 |
| 接收器收到事件上报 | 0 批 | 0 批 |

项目识别消费者位于 `chunk-vajj2ynj.js`：它使用同一个分类入口，在检测到 Android/iOS
工程时向共用系统消息队列加入 `dev_intent`。该队列也承载任务通知，不能整体替换为空操作。
这证明“核心工具还可运行”和“全部功能行为保持”不是等价的验收标准；本轮没有进一步验证
哪些宿主 UI 会消费这条系统消息。

后续改造应按用途拆分项目识别所需的探测与额外分类收集，并复核缓存及各消费者。当前的
整块停用实验存在已观察到的行为损失，不能直接升级为生产策略。相同混淆符号在其他模块中
还可能表示不同函数；分析必须以模块路径、摘要和导出绑定为准，不能按名字全局替换。

## 本轮验证与证据强度

测试使用当前安装的完整 1.4.0 启动器与二进制、独立 HOME/配置、假 API key、本地 TLS
接收器及只连接本地服务的 CONNECT 夹具。测试代理仅用于接收审计流量，不加入日常架构。
测试 CA 仅通过测试子进程环境加载，不关闭 TLS 证书校验，不修改系统信任库。

1. 普通模式：3 轮模型请求、Bash / Read 完成，收到 2 批事件上报，作为正对照。
2. 现行 optional-off：相同任务完成、0 批事件上报；业务附加字段仍在。
3. optional-off + 本地条件开关：任务完成，3/3 模型请求包含条件性环境信息头。
4. optional-off + 调用方观测：实际事件参数已构造；项目配置读取和系统消息消费者均被触发。
5. optional-off + 实验性整块停用：项目配置读取归零，同时观测到系统消息消失。

接收器独立于 Claude 进程，可验证请求是否到达它；第 4、5 项另含进程内观测，不能冒充
完全未插桩运行。测试的 `passed` 表示符合审计预期，**包括第五项预期出现的行为变化**，
不表示实验性策略可以发布。最后一次运行的事件字段统计是运行样本，受启动时序影响，不作为
“所有字段数量”或稳定的升级门槛。

本轮通过二进制中的嵌入路径枚举，读取了 2,346 个可访问 JavaScript 模块；另有 8 个路径
候选不可读取。枚举和关键词检索用来定位候选，详细追踪只覆盖本报告列出的路径，不能据此
声称审计了所有模块语义、native 代码或所有外发。原程序文本仅保存在本地忽略目录，未纳入
仓库或发布包。[可公开证据摘要](audits/2.1.296-dataflow.json)只保留标识、摘要、字段名及计数。

在包含本轮工具的源码目录复现当前版本的审计；它不属于自动安装验收门槛：

```bash
python3 tests/privacy-dataflow.py \
  --root "$HOME/.local/share/claude-termux/current/runtime" \
  --output "$PWD/build/dataflow-audit-new"
```

输出目录必须尚不存在，并位于安装版本目录以外。组件观测的版本绑定集中在
`tests/privacy-dataflow-profile.json`，模块摘要不匹配会拒绝观测。
工具本身与实验开关不改变持久模式或生产隐私档案。
TLS 证书生成器的扩展另经过原有 HTTPS / WSS / SNI / 错误证书拒绝测试。

## 后续优先级

1. **按用途拆分项目采集。** 保留项目识别系统消息所需输入，避免为被关闭的遥测读取额外
   软件仓库、环境配置。必须以 Android/iOS 项目识别与核心工具共同作为验收条件。
2. **逐字段评估正常请求中的附加信息。** 为模型 metadata、工具耗时、诊断、归因文本和
   功能开关属性分别标注业务用途、是否可缺省及调用路径；本地模拟 API 接受删字段不能证明
   真实服务契约允许它。条件性环境头的真实服务依赖也尚未验证。
3. **继续追踪事件调用方。** 优先处理只为上报执行的探测；对正常业务已经需要的数据，
   区分“停止额外组装/保存”和“停止业务读取”，避免误伤功能。
4. **再评估 DNS 接口替换。** 比较当前私有协议依赖与其他桥接方式的维护、进程、性能和
   平台成本；在没有候选验证前，不将“更低层”或“更少进程”当作优越性的充分理由。

真实登录、Remote Control、Trusted Devices、不同服务提供方、其他设备/ROM、未知 native
出口、服务端数据用途与保留规则均未得到本轮验证。这些限制与已观察到的客户端行为分别记录。
