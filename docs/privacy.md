# 可选上报控制

适配器 1.4.0 提供 `optional-off` 模式：在已验证的 Claude Code 二进制中停用已确认的
可选上报入口、初始化和导出组件。默认仍为 `standard`，保留用户原有的 Claude 设置。
安装或升级适配器本身不会替用户启用这个选项。

这里的“可选上报”包括功能使用事件、运行诊断、错误报告和遥测导出，并不只指匿名计数。
这些收集或发送动作不能因为被称为“使用统计”就视为完成用户任务所必需的功能。
模型请求、登录、用户主动使用的远程会话等业务通信与它们分别处理。
官方总开关同时参与其他功能的可用性判断，因此为了保留功能而不设置总开关，
不代表用户希望保留可选上报。本模式直接停用已验证的具体上报组件，保留共享功能判断；
已经验证的功能与尚未验证的范围见下文。

这不是零数据外发保证。模型请求、登录、功能开关获取、远程会话、工具联网等业务流量仍然
存在，其中可包含身份、设备和会话标识、提示词、工具结果及完成任务所需的上下文。客户端
补丁不能约束服务端保存、关联或推断这些信息，也不构成操作系统网络隔离。

## 使用

```bash
claude-termux-manage privacy                  # 查看持久设置和当前版本支持情况
claude-termux-manage privacy optional-off     # 本地自检通过后，关闭已确认的可选上报
claude                                      # 新进程使用所选模式
claude-termux-manage privacy standard         # 恢复用户原来的 Claude 隐私设置
```

模式保存在安装数据目录中的 `privacy-mode`，原子写入、权限 0600，独立于 Claude 的
`settings.json`，更新与回退不会覆盖它。切换后需要结束并重新启动已有的 Claude 会话及
后台进程；正在运行的进程保留启动时的策略。检查命令不会把旧进程标为已经受到保护。

临时选择可以使用 `CLAUDE_TERMUX_PRIVACY=optional-off claude` 或
`CLAUDE_TERMUX_PRIVACY=standard claude`。显式选择优先于持久设置。原生执行层会向
直接自启动的同一个 Claude 二进制传递所选关闭策略，即使调用方重建子进程环境。
持久设置还会在每次 ELF 加载时独立读取，因此不依赖启动包装器或父进程存活。
直接使用绕过适配器的官方二进制、旧适配版本或主动破坏加载链不在保证范围。

不设置 `DISABLE_TELEMETRY`、`DISABLE_GROWTHBOOK`、
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 等共享功能开关。关闭模式在进程内设置
错误上报、反馈命令和调查的专用关闭项，并停用遥测内容记录；不会改写用户配置文件。
关闭模式也会阻止用户配置的第三方 OTel 导出，因此需要这些监控数据时应使用 `standard`。

## 控制位置

1. ELF 的兼容库读取模式，在 Bun 执行主程序前加载本版本的 `termux-privacy.mjs`。
   适配器只检查和修改指定 Claude 进程；继承 `BUN_OPTIONS` 的其他 Bun 程序不会被修改。
2. 校验 Bun 版本以及配置档案中 21 个嵌入模块的 SHA-256。随后通过 Bun 的模块替换接口
   更新导出绑定；当前引擎中，模块内部的调用也使用更新后的绑定。原有官方文件内容保持不变。
3. 先停用事件总线，再停用第一方事件初始化，避免创建会自动回放旧失败队列的发送器；
   同时停用独立的 Datadog 队列、错误上报、反馈提交、遥测初始化和详细追踪开关。
4. 停用 Log/Meter 生产组件，并覆盖日志、指标、追踪各自的 HTTP JSON、HTTP protobuf、
   gRPC 导出器。远程 runner API 的诊断上传方法单独停用，保留注册与心跳等业务方法。
   在初始化前及应用用户设置后的遥测初始化位置关闭独立的原始 API 内容文件记录。
5. 请求层补充处理已确认的事件、指标、反馈、runner 诊断与 Datadog 地址，覆盖 fetch、
   Node HTTP/HTTPS、HTTP/2。OTLP 对自定义地址的发送由导出器停用负责，不能仅依赖 URL。
6. 两种 Worker API 都注入控制层，同时更新静态导入绑定。自启动进程通过原生库再次加载。
7. 单独替换内置 `cc-plugin-telemetry` 的 Hook 模块：`telemetry.log` / `telemetry.mark`
   接受调用但不读取载荷，保留原来的调用来源限制；不安装收集所用的引擎、会话生命周期处理函数。
   替代模块声明的环境、文件、进程、网络与定时器调用能力为空。其他插件继续使用原来的注册工厂。

内置插件遥测的原始实现会在发送前读取身份配置、环境和仓库信息，并执行运行环境探测。
仅拦截请求不能阻止这些本地收集动作。1.3.1 补上了这个收集入口；其中邮箱字段在原代码中
仅随 `USER_TYPE=ant` 分支加入，普通外部用户分支的对照测试没有邮箱字段。这是针对这一组件的
观察，不能推导其他业务请求也没有身份信息。

停用事件总线不会撤销调用方在传入参数之前已经完成的读取或计算。1.4.0 的进一步数据流
审计确认：普通事件调用方仍构造参数；另一个项目环境分类器仍读取测试项目的 `.npmrc` 和
`.envrc`，其结果还被项目识别系统消息使用。模型与功能开关请求也仍携带配置级设备标识、
会话标识等附加信息。直接停用整个项目分类器的隔离实验停止了读取，同时移除了 `dev_intent`
系统消息，因此没有应用到日常策略。来源、控制阶段、对照结果与后续切入点见
[架构与数据流审计](architecture-review.md)。

HTTP/2 中混用业务与可选请求的会话仍可以建立连接；请求层只丢弃匹配的请求，不能据此
声称从未与服务端建立连接。纯 Datadog intake 的 HTTP/2 会话使用本地替代对象。

已经存在的遥测队列不自动删除。关闭模式不会回放它们；恢复 `standard` 后由官方逻辑处理。
普通会话历史、用户主动开启的其他调试日志及第三方工具文件也不由此功能清理。

## 验证与更新

当前档案针对 **Claude Code 2.1.296 / Bun 1.4.3 / 官方 ARM64 musl 包**。
原始二进制 SHA-256 为
`b0bbc936a82930933d7d5645081050d5f827a946cf6abc6575383b777a0feec0`。
档案只含版本、模块标识与摘要，不分发官方程序源码。

候选安装会比较官方文件的摘要，并在本地接收器上运行原程序组件的对照测试，再运行完整
CLI 工具和后台会话测试。发现未知版本或测试失败时，已选择关闭模式的安装保留当前版本
及模式。档案的最低保护修订号为 2；回退到缺少内置插件收集控制的 1.3.0 或更旧适配器也会
拒绝，必须先明确选择 `standard`，避免名称相同的模式悄悄减少保护范围。
启动阶段出现模块摘要或 Bun 版本不匹配会在主程序运行前报错退出，不静默降级。

**关闭模式不能承诺官方发布后立即升级。** 官方改变内部模块时，需要复核新的档案与行为。
默认模式仍按一般兼容性验收跟随官方更新；它不会因为缺少隐私档案而拒绝新版。

1.4 将模块符号与测试入口集中到 `libexec/privacy-profiles/` 的版本档案，通用控制层使用
语义角色引用导出，避免每次重命名都修改多处策略代码。安装时选择相应档案，运行时仍校验
全部模块摘要。这个重构降低维护成本，不意味着能够自动判断新版函数的语义。
发布清单签名覆盖已验证版本索引；更新器在下载和构建前检查。渠道目标尚未验证时，使用不
超过该目标的最新已验证版本，或暂缓升级；适配器本身仍可升级到支持当前 Claude 的新版。
明确指定的版本不会被替换为其他版本。实际文件摘要和行为验收仍是激活候选版的必要条件。

设备验证使用隔离配置、假测试密钥和合成数据，没有登录真实账号或调用付费模型：

| 检查 | 结果 |
| --- | --- |
| 9 种真实内置 OTLP 导出器 | 原始组件可发送；关闭后接收器收不到导出 |
| 事件、指标、反馈 × fetch/HTTP/HTTP2 | 原始模式 9 次上报；关闭后 0 次 |
| 模型与功能开关路径 × 上述 3 种传输 | 两种模式都保留 6 次业务请求 |
| HTTP 与 HTTP/2 静态命名导入 | 另 2 次事件上报被阻止，另 2 次业务请求保留 |
| 事件缓冲、日志生产与 Datadog 队列 | 原始组件产生记录；关闭后为 0 |
| 内置插件遥测，普通外部 / `ant` 两种合成环境 | 每组原始组件读取环境 140 次、身份配置 1 次、发送 2 条事件；关闭后读取、探测、排队定时器与发送均为 0 |
| 内置插件调用契约 | 保留来源限制、会话与引擎延续、其他插件注册；关闭模式不读取事件载荷，含指向 collector 的调用 |
| 历史失败队列 | 原始初始化处理测试队列；关闭后不读取和回放的初始化路径被停用，测试文件保持原样 |
| 两种 Worker API，各含默认与显式环境 | 关闭策略生效，事件请求被停用 |
| 精简环境直接自启动 | 关闭策略继续生效 |
| 实际 CLI 的 Bash、Read、Write、Edit、Grep、Glob、Hook、MCP | 通过，无需开启两个总关闭开关 |
| 实际 daemon 与后台 session | 被观测的进程均加载控制层，工具任务完成 |
| 显式开启原始 API 文件记录 | 对照生成 17 个文件；关闭模式前台与后台均为 0 |
| 模块摘要、引擎版本或模式损坏 | 启动前拒绝；不运行未保护的主程序 |
| 未支持的更新/回退与自检失败 | 保留已工作的版本、模式及用户设置 |

可复现的组件测试：

```bash
python tests/privacy-smoke.py --root /完整候选版本/runtime --report /临时目录/privacy.json
python tests/device-smoke.py --root /完整候选版本/runtime --privacy optional-off
python tests/device-smoke.py --root /完整候选版本/runtime --privacy optional-off --background
python tests/test-privacy-policy.py
```

关闭模式的安装路径暂不支持空白字符，因为当前 Bun 的 `BUN_OPTIONS` 参数解析不会按
Shell 规则去除路径引号；遇到这种路径会明确拒绝启用，不带着失效的保护继续启动。

## 尚未证明的范围

分析包括反查嵌入的 JavaScript 与实际执行组件，但不等于整个 native/JavaScript 程序的
完整控制流审计。内置遥测插件已增加直接组件验证和真实 CLI 调用验证，但尚未穷尽账号专属
开关、Remote Control、Trusted Devices、云端 worker、所有其他内置插件和第三方扩展的路径；
原生崩溃与直接系统调用的网络出口也没有全覆盖证明。
测试了 runner 诊断 API 方法的替换，不代表完成真实自托管 runner 或远程控制验收。

新端点、动态加载代码、独立的 MCP/工具进程或有意绕过控制层的调用仍可能外发数据。
普通业务 API 里的标识和服务端风控规则也没有删除或伪造。
因此，此模式的准确含义是“关闭已验证的可选上报路径”，不是“彻底移除所有隐私搜集”。
