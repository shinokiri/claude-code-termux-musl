# 按用途拆分项目采集：1.5.0

针对 Claude Code 2.1.296 / Bun 1.4.3，`optional-off` 在项目分类的入口停止不必要的采集，
保留 Android／iOS 应用项目识别。它不是文件访问沙箱，也没有改写用户项目。

## 问题与控制点

1.4.0 的事件总线已关闭，但初始化事件的参数仍调用共享项目分类器。原版函数读取软件源、
密钥管理器、CI 等配置，返回 16 类项目特征。另一消费者用其中两个布尔值触发正常的
`dev_intent` 系统消息。将整个函数替换成 `null` 会停止读取，也会移除这些消息。
原始证据保留在[1.4.0 数据流审计](architecture-review.md)中。

新策略只替换这个共享函数，返回 iOS／Android 应用项目判定。其他导出保持原样。
新增摘要绑定覆盖原分类器、目录上下文、仓库工具，以及已检查的初始化和项目识别消费者。
消费者变动也必须重新复核，不根据函数名称猜测新版契约。

| 处理 | 1.5.0 optional-off |
| --- | --- |
| `.npmrc`、`.envrc`、其他软件源／密钥配置 | 本入口不再读取，不再构造相应分类 |
| CI、Docker、锁文件、Nix、Bazel、非移动工具链类别 | 本入口不再计算，CI 子目录不再探测 |
| Android 项目 | 保留 manifest 名称识别及必要 Gradle 文件读取，包括版本目录与 `android` 子目录 |
| iOS 项目 | 保留相关子目录、最多 5 个 Xcode 项目、尾部最多 1 MiB 的项目设置判定 |
| iOS 判定规则 | 通过只含合成工具结果封装的输入，复用原来的纯文本证据解析函数；不执行工具，不产生会话消息或事件 |
| 缓存与上下文 | 复用原主机范围 LRU、工作目录、失效机制和远程模式／HOME 仓库排除逻辑；未知结果允许重试 |
| 正常工具 | 保留 Read／Bash 读取配置的能力；用户主动请求的读取不受本入口限制 |

目录枚举仍会看到文件名，这是当前项目识别所需的输入。Gradle 读取沿用 64 KiB 上限，
文件内容读取继续使用原有 `noFollow` 有界读取函数。目录／文件符号链接、未知 iOS 判定、
读取失败及项目数上限保持已验证版本的行为。未宣称目录遍历完全没有并发文件变更风险。

## 验证

`tests/privacy-project.mjs` 在原程序组件上比较 48 个场景：Android 插件类别、四种 Gradle
文件、版本目录、嵌套项目、iOS 平台设置、条件设置、非 iOS 反例、大小上限、项目数量上限、
符号链接、缓存复用／刷新、目录切换、读取失败／重试和禁止本地扫描的上下文。
测试独立观察 `open`、`readFile`、`readdir`、`lstat`，不只观察包装后的有界读取接口。
合成测试的逐项读取记录、CLI 结果及受测源码摘要见
[机器可读证据](audits/2.1.296-project-privacy.json)。

`tests/privacy-dataflow.py --project-check` 是安装和升级的强制验收项：独立配置、假 API
key、本地 TLS 接收器驱动实际 CLI 完成 Bash 和 Read，保留两个 `dev_intent` 系统消息。
接收器只保存字段名、合成标记检查和计数，不保存请求体或标识值。它与普通工具、后台任务、
网络、Worker 和直接自启动等原有验收共同运行。

## 仍有的边界

这修复一个已确认的混合用途采集入口，不是所有事件调用方的清零证明。其他正常请求里的
设备／会话标识、工具耗时、归因和条件性环境头不在本次删除范围。登录、真实模型服务、
Remote Control、未知 native 出口及服务端数据处理没有新增验证。

最低保护修订号升到 3。未知版本仍暂缓升级；已选择 `optional-off` 时不能直接回退到
仍执行原共享采集的 1.4.x。原版二进制、嵌入源码和真实用户配置均不随适配器发布。
